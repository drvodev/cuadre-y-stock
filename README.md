# Inventario y caja — base inicial

Proyecto Maven para abrir en IntelliJ IDEA: **File > Open**, elegir esta carpeta o `pom.xml` y cargar como proyecto Maven. Configurar un JDK 21 o superior. Para comprobar la compilación y las pruebas, usar el ciclo Maven `test`; para ver la ventana provisional, ejecutar `javafx:run` desde Maven.

Esta es una estructura para revisar, no una beta funcional. Las clases de modelo, vistas, controladores y servicios están vacías intencionalmente; las interfaces son puntos de partida sin contratos todavía. Se definirán y probarán por módulo. No hay conexión configurada, tablas, migraciones, transacciones ni datos reales. El controlador PostgreSQL está declarado para el trabajo posterior; requiere una instalación y configuración de base de datos independiente.

El paquete `modelo.stock` separa el inventario de `modelo.caja`; `servicio.puerto` reserva contratos entre módulos. Los repositorios serán contratos de persistencia, no implementaciones. `excepcion` contiene excepciones básicas y `src/test` las pruebas. La ventana solo confirma el arranque de JavaFX.

Stock: `SaldoStock` y `StockService` calculan movimientos con cantidades exactas; el descuento usa únicamente el disponible. `ReservaService` vincula cada reserva a una separación, informa cuánto hay disponible y cuánto falta, y registra la cantidad aceptada, ampliaciones, cancelaciones y despacho. Puede ampliarse después de un ingreso; exige tener la cantidad completa reservada antes de despachar. `ConfirmacionReservaView` prepara el aviso de confirmación, pero todavía no está conectado a una pantalla operativa.

`InventarioService` registra stock inicial, entradas, ventas y ajustes con identificadores de solicitud; guarda el cambio real y mantiene el historial. `StockMemoriaRepository` sirve para pruebas y pierde los datos al cerrar. Se preparó `StockPostgresRepository` y el esquema `src/main/resources/db/stock-v1.sql`, con transacciones, consultas parametrizadas y deduplicación. **La implementación PostgreSQL aún no se ha probado contra un servidor real ni está conectada a las pantallas; no utilizar con datos reales.** La aplicación todavía no configura credenciales ni aplica el esquema automáticamente.

Pendiente: integrar el aviso en la pantalla de separación, conectar el autorizador de despacho a Caja y garantizar que la validación del pago y el despacho sean atómicos en una transacción compartida; conectar compras, definir mínimos por almacén y completar migraciones y pruebas PostgreSQL con concurrencia, recuperación y reintentos. El autorizador usado en pruebas es simulado; no existe uno de producción. El catálogo queda para una etapa posterior. Los cálculos de Stock no autorizan por sí solos una entrega ni confirman pagos. No usar el esquema con datos reales antes de probarlo y versionar su migración.

Referencia: especificación beta 3.1, 5 de noviembre de 2026. Entre las reglas por implementar: ventas con stock cero no se bloquean, el stock nunca baja de cero y los ítems libres no afectan stock; ventas completas o separaciones con abonos; cierre manual y reportes .xls. No se han resuelto los detalles pendientes del plan. La relación entre reservas, stock insuficiente y entrega requiere definirse antes de programarla.
